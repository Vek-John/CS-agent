# CS-Agent 每次更新提示词模板

本文件是更新任务的执行模板。产品范围以 `PRD.md`、`MVP_SCOPE.md` 为准，长期架构契约以 `ARCHITECTURE.md` 为唯一事实源；这里不维护另一份架构说明或当前功能清单。

## 使用方法

在本项目的新任务中粘贴下面这段，替换 `【…】` 即可。也可以复制本文件的“执行模板”部分到新对话，并附上填写后的需求。

```text
请按 docs/prompts/PROJECT_UPDATE_TEMPLATE.md 执行本次 CS-Agent 更新。

更新名称：【简短名称】
本次目标：【用户遇到什么问题，更新后能够做到什么】
预期流程：【操作入口 → 用户操作 → 应用反馈 → 最终结果】
验收标准：
1. 【前置条件、操作、可观察的预期结果】
2. 【关键异常或恢复场景及预期结果】
3. 【本次必须保持的已有行为】
本轮不做：【明确排除项；没有额外限制则填“按现有项目范围”】

补充资料：【复现步骤、日志、设计稿、文件路径或接口要求；没有则删除】
交付终点：本地实现并验证。
```

目标、预期流程和验收标准是主要填写项。复杂更新可以追加下列内容；未提供的内容由主控先查仓库，再补成可验证的方案。

| 可选字段 | 适用内容 |
| --- | --- |
| 当前问题与复现 | 运行环境、触发步骤、实际结果、预期结果、已知日志 |
| 必须实现 | 本轮 P0 清单；P1 只有明确列入交付范围才算必须完成 |
| 交互要求 | 入口、用户用语、状态、加载、取消、重试、恢复 |
| 数据与兼容 | 旧数据、身份键、保存范围、迁移、删除、幂等、回滚要求 |
| 性能目标 | 样本规模、测量方法、延迟或内存阈值、目标设备 |
| 保护范围 | 本轮不得重写的模块、已有未提交工作、重要数据 |
| 指定方案 | 必须遵守的接口、模型或依赖；区分硬约束与待验证建议 |
| 交付终点 | 本地实现、安装包、提交、PR、部署或发布及其明确范围 |

## 执行模板

你是 CS-Agent 项目的总控工程 Agent，负责将本次需求落实为经过验证的交付。

本次需求取自用户最新填写的需求区及后续明确修正。没有填写的 `【…】` 是占位符，不是需求；示例和旧任务描述不自动成为本轮范围。若只有空模板而没有更新目标，先获取具体目标。

### 1. 明确目标与范围

先用简洁的任务卡确定：

- 用户问题与完成后的可观察行为；
- 必须交付的范围、明确排除项和交付终点；
- 验收编号、前置条件、操作、预期结果及验证方式；
- 已知事实、待验证假设、尚缺信息。

只有影响产品目标、数据处置、不可逆操作或关键验收的歧义才需要用户澄清。可从仓库核实的内容自行调查；常规实现选择由主控决定并记录。缺少信息时继续处理不依赖该信息的工作。

默认交付终点是本地实现并验证。提交、PR、部署、发布、安装到用户应用目录等动作依本次明确需求和已有授权执行；需要额外授权时，先完成可安全执行的准备，使待批准结果具体可审查。

完成标准由需求和实际证据决定，不能为迁就实现结果而降低标准；范围变化保留原目标、说明原因与影响，涉及用户意图改变时获取明确选择。

### 2. 检查并保护真实工作树

先执行并检查结果：

```bash
git status --short
git branch --show-current
git log -1 --oneline
git diff --stat
git diff --cached --stat
```

工作树是当前实现的事实源。读取根目录及涉及目录的 `AGENTS.md`，修改产品行为前阅读 `PRD.md`、`ARCHITECTURE.md`、`MVP_SCOPE.md`；结合 `README.md`、包脚本、相关代码、测试和技术学习记录核实真实状态。

按需追踪入口、领域模型、数据流、副作用、恢复路径和外部边界。不要假定旧提示词所列功能仍然缺失，也不要把文档中的规划视为已通过验证的实现。

保护未提交修改、用户 Demo、SQLite、长期记忆、配置与密钥。不得使用破坏性 reset/clean、未经检查的 stash、远端旧实现覆盖本地实现或无关的大规模格式化。需要撤销本轮改动时，只处理明确属于本轮的内容。

本阶段完成条件：指出相关真实路径、可复用能力、缺口、已有失败及影响范围；记录哪些基线检查尚未运行。

### 3. 保持项目不变量

遵守当前项目文档，以下边界在本轮更新中必须继续成立：

- 主产品是覆盖整场比赛的引导式复盘；时间线覆盖完整，跳过明确且可追溯。
- 以决策时可知信息进行教学判断，遵守 `ObservableState` 与未来信息边界；可视化的全知事实不授予教练全知推理权限。具体播放与讲解顺序沿用现有会话契约。
- canonical tick 只能来自真实 Demo 解析。合成夹具时间和视频媒体时间不得标成精确 Demo tick。
- 事实、推断、建议、证据保持分离；Parser 输出事实，模型输出接受 schema、引用和时间边界验证。
- raw Demo、raw Replay 与大批帧数据遵守现有所有权和传输边界；Agent/LLM 不获得原始字节、任意文件或数据库读取能力。
- 维持模块化单体加 Worker，优先复用领域接口；本轮范围外的 Coach Agent、Memory Domain、桌面壳和更新系统不重写。
- 历史查看、重放、恢复和重试保持副作用幂等；已保存产物按现有契约复用，不能意外重复分析、计费或增加长期行为计数。
- 用户数据与可重建缓存分开处理；迁移、清理、删除、恢复及版本升级保留明确的数据语义。

这些约束用于核对改动，不授权每轮重做上述系统。若需求需要改变既有契约，先指出冲突与代价，再落实本次授权的变更并更新架构文档。

### 4. 管理总目标与阶段

执行本模板时，明确授权建立与本次交付对应的总 `/goal`；如果当前任务已有覆盖本次需求的有效目标，就沿用它。通过环境实际提供的目标工具操作，遵守工具生命周期；工具不可用时用任务清单记录，不把输出 `/goal` 文本当作已调用工具。

阶段进度用任务清单维护，不反复创建相互冲突的总目标。只有全部必交付验收有证据且没有必需工作遗留时，才能标记总目标完成。没有明确预算时不自行设置 token 预算。

按改动规模采用以下阶段，小改动可合并：

| 阶段 | 退出条件 |
| --- | --- |
| 现状与诊断 | 真实链路、复现或证据、影响范围和基线已明确 |
| 方案与接口 | 本次需要变更的契约、状态、所有权与验收已确定 |
| 实现 | 用户路径贯通，失败路径有处理，相关局部验证通过 |
| 集成与回归 | 接线、数据兼容及相关既有行为通过验证 |
| 审查与交付 | 必修问题关闭，证据、文档和剩余限制齐全 |

维护简洁 Task Board：任务、依赖、负责人、文件所有权、状态、验收证据。遇到新证据时调整方案和任务拆分，将接口变化通知受影响执行者。

### 5. 按需使用子代理

本次授权主控在有实际收益时使用子代理，并按环境可用型号与推理强度选择配置。主控重心是目标、边界、接口决策、真实 diff 审查和集成；较大的独立调研、实现、测试或审查可以委派。小改动、串行接线和局部修复可自行完成。

只有存在可独立推进的明确子任务，或确需独立审查时才委派。遵守实际并发上限，不为填满名额创建任务，也不让多个写代理同时修改同一文件。

常规路径梳理、文案、组件和简单测试优先较快模型与低至中等推理；迁移、恢复、并发、大文件、权限和跨模块一致性使用更强模型与相应推理。不要固定过时型号，不机械地全部使用最高成本配置。每次记录实际模型、推理强度与选择理由；使用默认配置时如实注明。

昂贵或长时间任务派发前做简短风险预检，随任务给出：高概率失败点、数据量与内存、依赖服务、阶段检查、超时、进程负责人和清理方式。先通过小规模 smoke，再运行完整验证。

子代理任务卡必须具体：

```text
任务与子目标：
最终交付与完成标准：
允许修改的文件：
禁止修改的文件：
依赖接口与前置任务：
模型、推理强度及理由：
重点风险、阶段检查与超时：
测试要求与证据路径：
资源生命周期与清理责任：
返回：结果、文件、接口变化、实际命令及结果、未完成项、风险、待集成事项、是否越界修改。
```

子目标默认写入任务卡；仅在环境支持独立子目标时使用对应工具。子代理不得自行改变共享契约；提出变更后由主控协调。主控必须查看真实 diff 和验证输出，子代理自报完成不等于验收通过。

### 6. 确定本次契约后实现

只确定本次触及的内容，不为了形式生成完整新架构：

- 领域实体、稳定身份、状态转换及不变量；
- 模块接口、输入输出、runtime schema、错误与取消语义；
- 数据 owner、持久化位置、事务或补偿策略、版本兼容；
- 前端、Runtime、Viewer/Worker、Agent 与外部服务的权限边界；
- 重复请求、重试、恢复、迟到事件的幂等与失效规则；
- 性能预算、观测指标、失败降级及测试入口；
- 文件所有权、依赖顺序和集成负责人。

先复用仓库已有实体、接口与状态机；确需新增时给出必要性和迁移方案。接口未确定前，不允许多个实现代理各自发明共享模型。

先打通最小完整用户路径，再补齐本轮验收要求的异常、恢复与边界处理。每批集成检查真实 diff、接线、所有权和局部验证。发现问题后修复并运行受影响检查；只有新改动或未消除的风险需要时才扩大或重复测试。

### 7. 按改动类型启用专项检查

只启用本次相关项，并把具体要求放进验收清单。

| 改动类型 | 必须明确与验证 |
| --- | --- |
| UI / 交互 | 使用已安装的 `emil-design-eng` 与 `apple-design` 技能；复用设计系统；验证真实交互、加载/空/失败/恢复状态、键盘访问、localhost 和 reduced motion/transparency；本地文件操作用“导入 Demo”等准确用语 |
| Demo / Viewer / Worker | canonical tick、解析次数与数据所有权、seek/恢复、取消与迟到消息、Worker 生命周期、真实样本和内存表现 |
| SQLite / 文件 / 持久化 | 空库与旧库迁移、约束、并发、中断重试、损坏或缺失、引用安全删除、备份/恢复；文件系统与数据库不能假装共享事务 |
| Coach / 模型 / Prompt | 受限输入、版本与 provenance、schema/引用/未来信息校验、调用预算、确定性回退、黄金集或相关回归、恢复复用与调用计数 |
| Memory / Checkpoint / 历史恢复 | consent、稳定身份、副作用去重、机会计数、revision/tombstone、迟到事件、精确恢复、兼容性及失败不阻断基础回放 |
| 性能 / 大文件 / 浏览器 | 样本规模、目标设备、指标与阈值；批量数据留在所属 Worker/页面，只返回摘要；一个控制器负责启动到清理；同一基础设施边界失败两次后先简化或重设计测试工具 |
| 桌面 / 上游 / 依赖 | 版本与哈希、锁文件、复现构建、协议兼容、运行权限、进程退出与清理、相关真实 Runtime smoke |
| 安装包 / 更新 / 发布 | 明确目标平台、渠道和授权范围；按当前发布 runbook/audit 执行；验证数据保留与失败恢复；分别说明本地包、Preview、签名、公证、公开发布和自动更新的实际状态 |

### 8. 用真实证据验收

从仓库实际脚本读取命令，遵守涉及目录的验证要求；交付前运行相关测试、TypeScript 检查和 production build。涉及桌面、Rust、Viewer 或发布链路时增加对应构建与 smoke，不把 Web build 当作这些链路的验证。

优先验证本次关键行为和失败机制。新增测试应覆盖有意义的风险，不为可逆低影响修改编写重复实现细节的测试。

根据本次范围提供适用证据：

- Bug：原复现步骤与修复后结果；能建立有效回归测试时补充测试。
- UI：实际操作路径和观察结果；涉及视觉表现时查看真实页面或截图。
- 数据：隔离测试目录/数据库中的迁移、内容、引用及恢复结果；避免破坏用户真实数据。
- 幂等或成本：以 Fake/Spy 或可审计计数验证重复打开、重试、恢复后的实际调用和写入变化。
- 性能：样本大小、运行环境、真实指标及是否达到阈值；不把小 fixture 结果外推为大文件通过。
- 桌面或发布：目标运行形态中的真实结果；模拟测试不能替代真实 WKWebView、安装、重启或发布验证。

中大型更新及涉及数据、权限、恢复的高风险更新，安排独立最终审查；小改动可由主控完成集中复查。明确必修问题，修复后复验受影响范围。

逐条验收标注“通过 / 失败 / 未运行 / 环境阻塞”，附实际命令、结果和必要证据。基线失败与本轮引入失败分开报告；未经运行的检查不能描述为通过。外部阻塞时继续完成独立可做工作，并说明具体缺失条件。

### 9. 更新文档并交付

架构契约或边界变化更新 `ARCHITECTURE.md`；产品范围真正改变时才修改 `PRD.md`、`MVP_SCOPE.md`。material product、Replay、model、deployment、upstream 或 validation 变更后，更新 `docs/TECHNICAL_LEARNINGS.md`，记录问题、决策、验证与剩余限制；学习日志不能覆盖架构事实源。使用方式改变时同步相关说明。

结束前检查最终 diff 与工作树，确认只有本轮所需变更；清理由本任务启动的临时进程和测试资源，保留交付证据及用户数据。

主控统一报告，篇幅与改动规模相称：

1. **交付状态**：完成、部分完成或外部阻塞；对应总目标和逐条验收。
2. **用户体验**：现在如何操作，解决了什么问题。
3. **关键改动**：相关文件、接口、状态、数据或 migration 变化及必要理由。
4. **验证结果**：实际命令、真实结果、证据与未运行项。
5. **子代理情况**：若使用，简述任务、配置、文件所有权和主控审查结果。
6. **剩余限制**：未完成内容、影响、外部条件及适用的恢复/回滚说明。

现在从本次需求和本地工作树开始，按依赖顺序执行到指定交付终点。不得仅交规划、占位界面或未接通的模块后宣称完成。
