# ADR-0001：真实地图事实与观察者知识状态分离

- 状态：Accepted
- 日期：2026-08-12
- 影响版本：ARCHITECTURE 1.0.0

## 背景

首个 localhost 纵向切片为了验证带看节奏，使用 CSS 示意 Mirage、0–100 百分比轨迹和 `observed_by_selected: boolean`。这能验证会话状态机，却不能支撑真实 Demo 回放和决策前教学：它无法稳定对齐 CS2 world 坐标，也无法表达脚步、枪声、最后已知位置、队友报点、身份不确定性和信息衰减。

完整 Demo 同时包含回放全知事实，例如隐藏敌人的真实位置、手持与库存；这些事实不能自动成为所选玩家在当时知道的信息。

## 决策

1. `MatchTimeline` 保存 CS2 world X/Y/Z 与逐时刻/变化点的完整玩家状态，包括解析器可得的生命、护甲、当前手持、库存、道具、经济和 C4 状态。
2. `MapSemantics` 通过版本化 `MapAssetManifest` 管理真实雷达、world→radar 仿射变换、楼层与地图语义。CSS 示意地图和百分比坐标退出 MVP 验收路径。
3. `ObservableState` 作为独立派生物，由多条 `ObservationClaim` 组成。每条 claim 明确来源、可用时间、空间/身份精度、共享范围、置信度、过期与证据引用。
4. 声音发射事件属于 Demo 事实；“观察者可能听到”属于带限制的推断；“观察者确实听到/队友确实报点”只有在可验证或用户明确补充时成立。
5. 全知回放和玩家已知视角共享 canonical tick，但使用独立数据与渲染图层。玩家已知视角不得显示隐藏敌人的实时真值位置或全知装备。
6. 雷达、武器和道具图标必须版本锁定并记录哈希、来源和权利状态。用户已确认 localhost 可下载并缓存参考站点所提供的 Valve 游戏资产；不得复制该站点的 UI、布局、组件、品牌和自有图标。公开发布前另行完成再分发审查。

## 后果

- Parser Adapter、TypeScript 领域契约和 Web 2D renderer 需要一次不兼容迁移，因此架构版本升级到 1.0.0。
- 地图、轨迹和装备状态可以像专业回放工具一样在同一 tick 精确同步。
- 教练分析可以区分“看见”“听到某方向”“最后在某处见过”“队友可能知道”和“用户补充报点”，未来信息门禁可以被自动测试。
- 声学遮挡、同时噪声和语音无法完全从 Demo 恢复；系统必须保留限制和置信度，不能追求虚假的确定性。
